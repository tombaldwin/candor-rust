## Summary
`Cache::get` in src/cache.rs was modified to fall back to reading `/var/cache/<key>` from disk when the in-memory map has no live entry for the requested key (either the key is absent or its TTL has expired). The fallback uses `std::fs::read_to_string`; a missing or unreadable file silently returns `None`, preserving the existing "not found" semantics. No external dependencies were added. The candor effect checker reports that `Cache::get` now carries a new `Fs` (filesystem read) effect, which propagates up through every caller: `service::Service::lookup`, `service::Service::batch`, `api::get_one`, `api::get_many`, and `report::build`, ultimately surfacing at `main`. Reviewers should be aware that code paths previously considered pure in-memory now perform blocking I/O, which may affect latency guarantees, testability (tests may unexpectedly pick up files under `/var/cache/`), and any capability-based security policies that audit filesystem access.
