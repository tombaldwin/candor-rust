## Summary
I added a remote fallback to `Resolver::resolve` in src/resolver.rs. When no fresh cached entry exists for a given IP (either the IP is absent from the map or the cached entry has exceeded the TTL), the resolver now attempts a TCP connection to `geo.internal:7070`, writes the IP string, and reads back the response as the location. A new private `remote_lookup` method encapsulates this logic, returning `None` on any connection or I/O failure (including DNS resolution errors for `geo.internal`). The rest of the codebase (`GeoService`, `api`, `report`) is unaffected because they all go through `Resolver::resolve`, which retains the same signature. Reviewers should be aware that `resolve` now performs blocking network I/O when the cache misses, which could increase latency in those call paths.
