## Summary
`Cache::get` in src/cache.rs now has a two-phase lookup: it first checks the in-memory TTL map (existing behaviour), and on a miss (or expiry) it attempts to read the file at `/var/cache/<key>` using `std::fs::read_to_string`, returning `None` if the file is absent or unreadable. No external dependencies were added; only `std::fs` and `std::path::PathBuf` from the standard library are used. The candor effect checker reports that `Cache::get` has gained the `Fs` (filesystem read) effect, which was not present in the baseline. This effect propagates through the entire call chain: `service::Service::lookup`, `service::Service::batch`, `api::get_one`, `api::get_many`, `report::build`, and ultimately `main` all now transitively carry the `Fs` effect. Reviewers should be aware that any caller of `Cache::get` may now perform blocking filesystem I/O, which could be a concern in latency-sensitive or sandboxed contexts.
