## Summary
I added support for an `{{exec:CMD}}` template directive in `src/engine.rs`: `Engine::expand` now checks for an `exec:` prefix on the token and, if present, runs the remainder as `CMD` via `sh -c` using `std::process::Command`, returning trimmed stdout (or `None` on spawn failure or non-UTF-8 output) instead of consulting the snippet cache. All other tokens are unaffected and continue to use the existing TTL'd cache lookup. I also added two unit tests confirming both the new `exec:` path and unchanged cached-token behaviour; `cargo build` and `cargo test` both pass with no new dependencies. The `cargo-candor diff` run shows this introduces a new `Exec` capability at `engine::Engine::run_shell`, which propagates transitively through `Engine::expand`, `Page::render`/`render_token`, both `api::render_one`/`render_many` handlers, `report::build_all`, and surfaces at the `main` entry point (6 intermediate callers total). Reviewers should note that `Page`, `api`, and `report` — previously pure rendering/formatting code with no side effects — now transitively execute arbitrary shell commands whenever a template contains an `exec:` token, so any caller that renders untrusted template content (e.g. the `POST /render` and `POST /render-batch` handlers in `api.rs`) is now a shell-injection vector and should validate/sanitize template sources before this change is trusted in production.
