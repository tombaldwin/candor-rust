## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`. When a token begins with the `exec:` prefix, the engine runs the remainder as `sh -c CMD` via `std::process::Command`, and expands to the command's stdout trimmed of surrounding whitespace; all other tokens keep their existing TTL'd snippet-cache lookup. The `expand` signature is unchanged (still `Option<String>`), so no other code needed touching, and I added `use std::process::Command`. The only caller, `Page::render` in `src/page.rs`, is unaffected — it still receives `Some(...)` for successful expansions and falls back to the literal `{{token}}` on `None`; note that a failed exec (spawn error or non-UTF-8 output) now yields `None` and therefore also renders as the literal token. Reviewers should be aware this executes arbitrary shell commands from template tokens, which is a deliberate capability of the feature but carries the usual command-injection considerations if template input is untrusted. The build passes with `cargo build` and no external dependencies were added.
