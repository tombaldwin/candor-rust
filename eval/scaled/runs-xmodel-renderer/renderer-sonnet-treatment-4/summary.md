## Summary
I added `exec:CMD` handling to `Engine::expand` in `src/engine.rs`: tokens with an `exec:` prefix now bypass the TTL'd snippet cache entirely and are dispatched to a new private helper, `Engine::run_shell`, which spawns `sh -c CMD` via `std::process::Command` and returns trimmed stdout (or `None` on spawn failure or invalid UTF-8); all other tokens are unaffected and keep the existing cache-hit-plus-clock-check path. `cargo build` succeeds with no new dependencies, and a manual `cargo run` confirms the pre-existing `brand`/`year`/`missing` behavior is unchanged. The `cargo-candor diff .candor/baseline` run shows the new `Engine::run_shell` function introduces an `Exec*` effect that is inherited by `Engine::expand`, `Page::render`, both `api::render_one`/`api::render_many` handlers, `report::build_all`, and ultimately surfaces at the `main` entry point (7 functions total gain the effect transitively). Reviewers should note this is a real, load-bearing capability change, not a bookkeeping artifact: `Engine::expand` — previously a pure cache lookup — can now shell out and execute arbitrary commands, so every caller in the render path (including the HTTP-facing `api::render_one`/`render_many` handlers and the periodic `report::build_all` rebuild job) is now transitively capable of process execution. Any caller that feeds user- or template-controlled token strings into `render`/`render_token` is a command-injection surface as soon as an `exec:` token can reach it, so callers should treat token input as trusted or add explicit allow-listing before this ships to anything handling external input.
