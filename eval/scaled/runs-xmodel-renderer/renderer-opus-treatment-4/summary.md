## Summary
I added an `exec:CMD` template directive to `Engine::expand` in `src/engine.rs`: when a token starts with the literal prefix `exec:`, the remainder is run through the system shell via `Command::new("sh").arg("-c").arg(cmd)`, and the token expands to the command's stdout, trimmed. All other tokens are unchanged and still go through the TTL'd snippet cache. The only new import is `std::process::Command`; no external dependencies were added. As a consequence for reviewers, `Engine::expand` gains a process-execution (Exec) effect, and because it sits at the bottom of the call chain that effect propagates up through every caller: `page::Page::render_token`, `page::Page::render`, `api::render_one`, `api::render_many`, and `main` all now transitively execute arbitrary shell commands whenever a caller-controlled token begins with `exec:`. The `cargo-candor diff .candor/baseline` run confirms this exactly, reporting `+Exec*` introduced in `Engine::expand` and inherited by those 5 intermediate callers up to the `main` entry point. This is a security-relevant surface: any token source reaching `render`/`expand` becomes a shell-injection vector, so callers should treat template tokens as untrusted or restrict who can supply `exec:` tokens.
