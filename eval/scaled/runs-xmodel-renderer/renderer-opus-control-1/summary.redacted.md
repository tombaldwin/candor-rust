## Summary
I added an `exec:CMD` directive to `Engine::expand` in `src/engine.rs`: when a token begins with the `exec:` prefix, the remainder is run through `sh -c` via a new private helper `run_shell`, and the token expands to the command's trimmed stdout. This path short-circuits before the snippet-cache lookup, so all other tokens keep their existing TTL'd cache behaviour unchanged. On failure (shell cannot be spawned, or the command exits non-zero) `run_shell` returns `None`, which preserves `expand`'s existing contract — the caller `Page::render_token` in `src/page.rs` then falls back to emitting the literal `{{token}}`, and `Page::render` inherits that behaviour token-by-token. No new dependencies were added (only `std::process::Command`), and the public signature of `expand` is unchanged, so no other call sites needed edits. Reviewers should note the security consequence: any token reaching `expand` with an `exec:` prefix now executes arbitrary shell commands with the process's privileges, so callers must treat template token sources as trusted input.
