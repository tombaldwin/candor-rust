## Summary
I added an `{{exec:CMD}}` directive to `Engine::expand` in `src/engine.rs`: when a token starts with the `exec:` prefix, the remainder is run through the system shell via `Command::new("sh").arg("-c").arg(cmd)`, and the token expands to the command's trimmed stdout; all other tokens keep their existing TTL'd snippet-cache behaviour. This required importing `std::process::Command` (no external dependencies). The `the analysis run confirms this introduces a new `Exec` effect in `engine::Engine::expand`, which propagates as a gained effect to every caller in the graph: `page::Page::render_token`, `page::Page::render`, `api::render_one`, `api::render_many`, and `main`. Reviewers should note the security consequence — the two `api` functions are the `POST /render` and `POST /render-batch` request handlers, so any template token supplied through those endpoints can now execute arbitrary shell commands; this is effectively a command-injection surface that should be gated, sandboxed, or restricted to trusted template sources before use in production. Also note that `expand` is no longer a pure/cheap table-lookup — for `exec:` tokens it now spawns a subprocess, so its previous "table hit plus a clock check" performance characterization no longer holds for that path.
