## Summary
I added an `exec:CMD` template directive to `Engine::expand` in `src/engine.rs`: when a token starts with the `exec:` prefix, the remainder is run through the system shell via `Command::new("sh").arg("-c")`, and the token expands to the command's stdout (trimmed), returning `None` on spawn failure, a non-zero exit status, or non-UTF-8 output. All other tokens keep their existing snippet-cache-plus-TTL behaviour, so the change is purely additive to the token grammar. The only new import is `std::process::Command`; no external dependencies were added and `cargo build` compiles cleanly. Running `the analysis confirms the consequence a reviewer must know: `Engine::expand` now carries a new `Exec` (process-execution) effect, and because it is called transitively, that effect propagates up through `page::Page::render_token`, `page::Page::render`, `api::render_one`, `api::render_many`, `report::build_all`, and `main`. This matters most for the HTTP-facing `api::render_*` entry points, which now allow attacker-influenced tokens to run shell commands, and for `report::build_all` (the periodic rebuild job) whose "rendering is cheap" assumption no longer holds, so callers should treat template tokens as untrusted and consider gating or sandboxing the `exec:` path.
