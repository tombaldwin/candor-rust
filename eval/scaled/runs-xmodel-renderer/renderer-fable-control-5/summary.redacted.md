## Summary
I added an `{{exec:CMD}}` directive to `Engine::expand` in `src/engine.rs`: before the snippet-cache lookup, `expand` now checks for the `exec:` prefix and, when present, runs the remaining string via `Command::new("sh").arg("-c")`, returning the command's trimmed stdout. Tokens without that prefix fall through to the existing TTL'd `HashMap` cache behaviour unchanged, so `year`, `brand`, and unknown tokens work exactly as before. This changes `expand` from a pure, cheap table-lookup into something that can spawn a subprocess, which affects every caller that funnels through it: `Page::render_token`/`Page::render` (src/page.rs), the `api::render_one`/`render_many` handlers, and the `report::build_all` rebuild job whose doc-comment explicitly assumes rendering is cheap. Reviewers should note the security and performance consequences — arbitrary shell execution driven by template tokens, and blocking subprocess spawns on request/rebuild paths that were previously latency-free; a failed spawn or non-UTF-8 output yields `None` (rendered as the literal `{{token}}`) rather than an error.
