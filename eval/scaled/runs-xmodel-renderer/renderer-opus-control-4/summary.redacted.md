## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`. When the requested token begins with the `exec:` prefix, the engine strips the prefix and runs the remainder through the system shell via a new private helper `Engine::run_exec`, which spawns `sh -c CMD` (using `std::process::Command`, no new dependencies) and returns the command's trimmed stdout; if the command fails to launch or exits non-zero, it returns `None`. All other tokens fall through to the unchanged TTL'd snippet-cache lookup, so existing snippets like `year` and `brand` behave exactly as before. Reviewers should note a behavioural consequence for the callers that go through this method: `Page::render_token` (and therefore `Page::render`, `api::render_one`, `api::render_many`, and `report::build_all`) will now shell out whenever a token starts with `exec:`, meaning template rendering is no longer a pure table/clock operation — it can spawn processes and block, which matters for the periodic rebuild job in `report.rs` that assumes rendering is cheap. Because `expand` takes `&self` and shells out on every call, `exec:` tokens are intentionally uncached and re-run each render, and a failed or unknown-to-shell command falls back to the literal `{{exec:CMD}}` text via the existing `unwrap_or_else` in `render_token`.
