## Summary

`Engine::expand` in `src/engine.rs` gained an `exec:CMD` template directive: when a token starts with `exec:`, the remainder is passed to the system shell (`Command::new("sh").arg("-c").arg(cmd)`) and the token expands to the command's trimmed stdout; all other tokens still use the TTL'd snippet cache. This turns what was a pure in-memory table lookup into a function that spawns a process and executes arbitrary shell input, so every caller in the render path now transitively performs process-execution effects. Directly affected are `Page::render_token` and `Page::render` in `src/page.rs`, which call `expand`; through them the API entry points `api::render_one` and `api::render_many` in `src/api.rs`, and `report::build_all` in `src/report.rs`, all inherit the effect. Reviewers should note that `report::build_all` is described as run by a periodic rebuild job assuming rendering is cheap, and the API handlers render caller-supplied token sequences, so both become command-injection sinks if any token reaching them is externally controlled. No input validation or allow-listing guards the `exec:` prefix, so the effect is reachable wherever untrusted template tokens flow.
