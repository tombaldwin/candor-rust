## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`. When a token starts with the `exec:` prefix, the remainder is run through the system shell via `Command::new("sh").arg("-c").arg(cmd)`, and the token expands to the command's stdout trimmed of surrounding whitespace; a new private helper `Engine::exec` encapsulates this and returns `None` if the command fails to launch or emits non-UTF-8 output. All other tokens fall through to the existing snippet-cache path unchanged, so `year`/`brand` behaviour is preserved. Reviewers should note the consequences that flow from `expand` returning `Some`: `Page::render_token` will now emit command output instead of the literal `{{token}}` for any `exec:` token, and everything layered above it (`Page::render`, `api::render_one`, `api::render_many`, `report::build_all`, and `main`) will transparently execute shell commands whenever an `exec:` token reaches them. This means the previously side-effect-free, cheap-and-cacheable `expand` now performs uncached shell execution on every call, which the periodic rebuild job in `report::build_all` and the `render`/`render-batch` HTTP handlers in `api.rs` implicitly assume is inexpensive — a security and performance consideration since `render_one`/`render_many` pass externally supplied tokens straight through with no allow-listing.
