## Summary
I added support for `{{exec:CMD}}` tokens in `Engine::expand` (src/engine.rs): when the token starts with `exec:`, the remainder is run via `sh -c` using `std::process::Command`, and the trimmed stdout is returned as the expansion (or `None` on spawn failure or non-zero exit), bypassing the snippet cache entirely — no external crates were needed. All other tokens are unaffected and still go through the existing TTL'd cache lookup. `cargo build` succeeds with no warnings. The `the analysis diff` run confirms the consequence for the rest of the codebase: the new `Engine::run_shell` helper introduces a fresh `Exec` effect, which propagates transitively through `Engine::expand` and `Page::render` into every caller — `api::render_one`, `api::render_many`, and `report`'s page-rendering path — and surfaces at `main` as a top-level `+Exec`. In practice this means any code path that renders a template (including the HTTP-style handlers in api.rs and the periodic static-site rebuild in report.rs, whose doc comment assumes "rendering is cheap") can now shell out to an arbitrary command if a caller supplies an `exec:`-prefixed token, so reviewers should treat template input as attacker-controlled and consider whether token sources need sanitizing before this ships to anything that accepts untrusted template strings.
