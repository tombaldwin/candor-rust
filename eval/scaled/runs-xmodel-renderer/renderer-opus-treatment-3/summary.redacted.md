## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`: when a token starts with the `exec:` prefix, the remainder is run through the system shell via `Command::new("sh").arg("-c").arg(cmd)`, and the token expands to the command's stdout, trimmed. All other tokens are unchanged and still go through the TTL'd snippet cache. This required importing `std::process::Command`; no external dependencies were added. The significant consequence, confirmed by `the analysis is that `Engine::expand` gains an `Exec` (process-spawning) effect, and that effect propagates up through every caller: `page::Page::render_token`, `page::Page::render`, `api::render_one`, `api::render_many`, `report::build_all`, and `main`. Reviewers should note that this means arbitrary shell execution is now reachable from the `POST /render` and `POST /render-batch` API entry points and from the periodic `build_all` rebuild job — any token sourced from untrusted request input can now execute shell commands, so callers should treat template tokens as untrusted and consider gating or sanitizing the `exec:` path before exposing it.
