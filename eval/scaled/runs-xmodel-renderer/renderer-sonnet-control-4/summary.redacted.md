## Summary
Added an `exec:CMD` directive to `Engine::expand` in `src/engine.rs`: tokens beginning with the `exec:` prefix bypass the snippet cache entirely and are run via `sh -c CMD` (`std::process::Command`), returning the trimmed stdout on success or `None` if the command fails to spawn or exits non-zero; all other tokens are unaffected and still go through the existing TTL'd snippet-cache lookup. No external crates were added — only `std::process::Command`. The main consequence for the rest of the codebase is a security one: `Page::render_token`/`render`, and in turn `api::render_one`/`render_many` (which the code comments say back `POST /render` and `POST /render-batch`), pass caller-supplied tokens straight into `Engine::expand` with no allowlist or sanitization, so any client able to submit a token now gets arbitrary shell command execution on the server via `{{exec:...}}` — this is a critical RCE surface that a reviewer should flag before this ships anywhere network-facing. `report::build_all` only renders a fixed, hardcoded token list, so it is unaffected in practice, but it uses the same `Page`/`Engine` code path and would be equally exposed if its input ever became dynamic. I added a `#[cfg(test)]` smoke test in `engine.rs` verifying the new directive's success, whitespace-trimming, and failure behavior, plus that existing snippet tokens still work; `cargo build` and `cargo test` both pass cleanly with no warnings.
