## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`: when a token starts with the `exec:` prefix, the remainder is run through the system shell via `Command::new("sh").arg("-c").arg(cmd)`, and the token expands to the command's trimmed stdout; any failure (spawn error or non-UTF-8 output) returns `None`, matching the existing cache-miss contract. All other tokens keep their unchanged TTL'd snippet-cache behaviour, and I added `use std::process::Command` (standard library only — no new dependencies). The crate builds cleanly with `cargo build`. Reviewers should note this introduces a process-execution (Exec) effect where none existed before: `cargo-candor diff` reports `Engine::expand` as the origin (`+Exec*`), and that effect propagates up through every caller — `page::Page::render_token`, `page::Page::render`, `api::render_one`, `api::render_many`, and ultimately `main` — so the entire render path is now capable of running arbitrary shell commands driven by template input. Because `expand` runs whatever string follows `exec:`, any caller that feeds untrusted or user-supplied token text into the render path becomes a shell-injection surface, which is the key security consequence to weigh before shipping.
