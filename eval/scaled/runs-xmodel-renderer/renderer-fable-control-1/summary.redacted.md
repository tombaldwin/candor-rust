## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`. When a token begins with the `exec:` prefix, the remainder is run through the system shell via `Command::new("sh").arg("-c").arg(cmd)`, and the token expands to the command's stdout trimmed of surrounding whitespace; if the process fails to launch, exits non-zero, or emits non-UTF-8 stdout, `expand` returns `None` (matching the existing "unknown token" contract). All other tokens keep their prior TTL'd snippet-cache lookup, so no existing behaviour changed. This required a new `use std::process::Command;` import. Reviewers should note the consequence for `Page::render_token` in `src/page.rs`: because `expand` returning `None` falls back to the literal `{{token}}`, a failed or non-zero `exec:` command now renders as the literal `{{exec:CMD}}` string rather than an error, and rendering any `exec:` token now spawns a subprocess and executes arbitrary shell input — a side effect and injection surface the previously pure `render`/`render_token` path did not have.
