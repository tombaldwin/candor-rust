## Summary

`Engine::expand` (src/engine.rs) gained a new branch: for any token of the form `exec:CMD` it now spawns a system shell (`sh -c CMD`) via `std::process::Command` and expands to the command's trimmed stdout, instead of only doing a cached snippet lookup. This turns what was a pure, in-memory table-and-clock operation into one that performs arbitrary process execution — a boundary effect with obvious command-injection exposure, since the command string comes straight from the token text. Every caller in the render chain now transitively inherits this effect: `Page::render_token` and `Page::render` (src/page.rs) forward untrusted tokens directly into `expand`. That reaches the request-facing handlers `api::render_one` and `api::render_many` (src/api.rs), meaning `POST /render` and `POST /render-batch` can now run shell commands on caller-supplied input. The periodic rebuild path `report::build_all` (src/report.rs) and `main` (src/main.rs) are likewise affected. Reviewers should treat all of these functions as newly process-executing / effectful and gate or sanitize the `exec:` token before this is exposed to any external input.
