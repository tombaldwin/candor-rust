## Summary

`Engine::expand` in `src/engine.rs` was changed so that a token of the form `exec:CMD` is no longer a snippet lookup: it now spawns a system shell (`Command::new("sh").arg("-c").arg(cmd)`) and expands to the command's trimmed stdout. This introduces a new **Exec** effect (arbitrary process/command execution) into what was previously a pure, in-memory table-and-clock lookup. Because the token string is passed straight to `sh -c`, any caller that can influence a token value can now run arbitrary shell commands, so this is a command-injection surface, not just a new capability.

The `cargo-candor diff` confirms the Exec effect originates in `engine::Engine::expand` and propagates transitively to `main` plus five intermediate callers that a reviewer must also treat as command-executing: `page::Page::render_token`, `page::Page::render`, `api::render_one`, `api::render_many`, and `report::build_all`. This is especially notable because `api::render_one`/`render_many` are the `POST /render` and `POST /render-batch` request handlers (remote input reaches the shell) and `report::build_all` runs on a periodic rebuild job that assumed rendering was cheap and side-effect-free. Every one of these functions should be re-reviewed as an Exec entry point before this change is accepted.
