## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`. Before the snippet-cache lookup, `expand` now checks whether the token starts with the `exec:` prefix; if so it runs the remainder of the token as a command via `sh -c`, captures stdout, and returns it trimmed. This required importing `std::process::Command`; no external dependencies were added. All other tokens are unchanged and still go through the TTL'd snippet cache. Consequently, `Page::render` in `src/page.rs` (the only caller of `expand`) now transparently supports exec tokens, and because expansion can now spawn a subprocess it is no longer a pure table/clock lookup — reviewers should note that expanding an `exec:` token carries the security and performance implications of shell execution (arbitrary command injection if tokens come from untrusted input). A failed spawn returns `None` so `Page::render` falls back to echoing the literal `{{token}}`, while non-UTF8 stdout is lossily decoded.
