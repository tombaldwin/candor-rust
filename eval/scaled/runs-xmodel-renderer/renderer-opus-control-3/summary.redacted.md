## Summary
I added an `exec:CMD` directive to `Engine::expand` in `src/engine.rs`. When the token starts with the `exec:` prefix, the engine now strips that prefix and runs the remaining string through a new private helper `Engine::exec`, which invokes `sh -c CMD` via `std::process::Command` and returns the command's trimmed stdout; the helper yields `None` if the shell fails to launch, the command exits non-zero, or stdout is not valid UTF-8. All other tokens are unchanged and still resolve against the TTL'd snippet cache. Only the standard library is used (`std::process::Command`), so no new dependencies were added. The consequence for the rest of the codebase is that `Page::render_token` in `src/page.rs` (and transitively `Page::render`) now transparently supports exec tokens through the same call, and on the `None` path an `exec:` token falls back to being echoed as the literal `{{exec:CMD}}`; reviewers should note that `expand` now spawns a shell subprocess and is no longer a pure, side-effect-free cache lookup, which has security (arbitrary command execution) and performance implications for any caller.
