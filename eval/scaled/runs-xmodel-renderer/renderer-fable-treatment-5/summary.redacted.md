## Summary

`Engine::expand` in `src/engine.rs` gained a new `exec:CMD` template directive: any token prefixed with `exec:` is now run through the system shell (`sh -c`) via `std::process::Command`, and the token expands to the command's trimmed stdout. This introduces a new **Exec** (process/command-execution) effect into a function that previously only did an in-memory cache lookup plus a clock check. Per `the analysis the effect originates in `engine::Engine::expand` and surfaces at the `main` entry point. Because token expansion is reached through the normal render path, several other functions now transitively perform Exec and should be reviewed: `page::Page::render_token` and `page::Page::render`, the HTTP handlers `api::render_one` (`POST /render`) and `api::render_many` (`POST /render-batch`), and `report::build_all` (the periodic static-rebuild job). The security-relevant consequence is that the public HTTP render endpoints and the background rebuild job can now trigger arbitrary shell execution whenever an untrusted template contains an `exec:` token — an injection surface a reviewer must weigh before this ships.
