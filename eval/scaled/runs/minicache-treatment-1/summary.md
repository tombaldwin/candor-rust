## Summary
I modified `Cache::get` in `src/cache.rs` so that on a cache miss — whether the key is absent or its TTL has expired — it falls back to a new private helper `load_from_disk`, which reads `/var/cache/<key>` via `std::fs::read_to_string` and maps any I/O error (missing or unreadable file) to `None`, satisfying the "treat as not found" requirement. Only the standard library is used (`std::fs` and `std::path::Path`), so no dependencies were added, and `cargo build` succeeds cleanly. The key consequence reviewers should know is a capability change surfaced by candor: `get` (previously a pure in-memory hash lookup) now performs filesystem I/O, and that new `Fs` effect propagates transitively through every caller — `Service::lookup`/`batch`, `api::get_one`/`get_many`, `report::build`, and ultimately `main`. This matters most for `report::build`, whose doc comment states it is called on a tight dashboard-refresh interval and "assumes it's cheap," yet it will now hit the disk for every uncached/expired key (notably `u3`, which is never cached) on each call. No call sites needed updating since the public signature of `get` is unchanged, but the latency and side-effect profile of these previously-cheap read paths has changed.
