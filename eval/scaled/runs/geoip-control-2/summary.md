## Summary
I added a remote fallback to `Resolver::resolve` in `src/resolver.rs`. When there is no fresh (within-TTL) cached entry for an IP, it now calls a new private `resolve_remote` method that opens a `TcpStream` to `geo.internal:7070` (a new `GEO_SERVER` constant), writes the IP as bytes, reads back the location string, and returns it trimmed; any connect/write/read failure or an empty response is treated as `None` ("not found"), as specified. Only the standard library is used (`std::net::TcpStream`, `std::io::{Read, Write}`), so no dependencies were added. Reviewers should note a behavioral consequence: `resolve` is now potentially blocking on network I/O, which propagates through `GeoService::locate`/`batch` and into `api.rs` and especially `report::summary` — the latter's doc comment states it runs on a tight interval and "assumes it's cheap," so each cache miss there will now incur a synchronous TCP round-trip (and a full connection-timeout stall if the server is unreachable). The remote call has no explicit connect/read timeout, so an unresponsive (but reachable) server could hang the calling thread; adding `connect_timeout`/`set_read_timeout` would be a sensible follow-up if that matters.
