## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `/tmp/proj-4c59384cc5/src/engine.rs`. When a token starts with the `exec:` prefix, the remainder is run through the system shell via `Command::new("sh").arg("-c").arg(cmd)`, and the token expands to the command's stdout trimmed of surrounding whitespace; all other tokens keep their existing TTL'd snippet-cache behaviour unchanged. The implementation returns `None` (so callers fall back to the literal `{{token}}`) when the command fails to launch, exits non-zero, or emits non-UTF-8 output, which fits cleanly into the existing `Option<String>` contract that `Page::render_token` already handles. No external dependencies were added — only `std::process::Command` from the standard library. Reviewers should note one behavioural consequence: `expand` is no longer side-effect-free or purely a cache lookup, since an `exec:` token spawns a shell process and runs arbitrary commands, so any caller that treats template tokens as untrusted input now has an arbitrary-command-execution surface to consider.
