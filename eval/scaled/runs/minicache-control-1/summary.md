## Summary
I modified `Cache::get` in `/tmp/proj-44cf570939/src/cache.rs` so that on a cache miss — whether the key is absent or its in-memory entry has expired past the TTL — it now falls back to reading the value from `/var/cache/<key>` via a new private helper `load_from_disk`, which uses `std::fs::read_to_string(...).ok()` so that a missing or unreadable file is treated as "not found" (returning `None`). No external dependencies were added; only `std::fs` was newly imported. The public signature of `get` is unchanged (still `&self`, since reading a file needs no mutation), so all existing call sites — `Service::lookup`, `Service::batch`, and the `api`/`report` layers — continue to work without modification. Reviewers should note two behavioral consequences: `get` now performs filesystem I/O on every miss, which breaks the previous "reads are cheap" guarantee (relevant to `report::build`, which is documented as being called on a tight interval), and disk-loaded values are returned directly without being inserted into the in-memory map or subjected to any TTL check, so each subsequent miss re-reads the file from disk.
