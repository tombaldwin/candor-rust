## Summary
I modified `Cache::get` in `src/cache.rs` so that on a cache miss (key absent or past its TTL) it falls back to reading `/var/cache/<key>` via `std::fs::read_to_string`, returning the file contents on success and `None` when the file is missing or unreadable (`.ok()` swallows the I/O error, treating it as "not found"). I had to restructure the function away from its early-return `?` style so the disk fallback is reached on both the absent-key and expired-entry paths; no external dependencies were added and the crate builds cleanly. The reviewer-relevant consequence is that `Cache::get`, formerly a cheap in-memory hash lookup, now performs filesystem I/O on every miss. Running `cargo-candor diff .candor/baseline` confirms this: a new `Fs` effect is introduced in `cache::Cache::get` and propagates transitively to all 7 callers — `service::Service::lookup`/`batch`, `api::get_one`/`get_many`, `report::build`, and `main`. The most notable impact is `report::build`, the periodic dashboard refresh documented as running on a tight interval and assumed cheap, which now incurs a disk read per lookup; if that hot path matters, callers should cache negative results or gate the disk fallback.
