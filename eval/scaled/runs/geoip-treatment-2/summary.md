## Summary
I added a remote fallback to `Resolver::resolve` in `src/resolver.rs`: on a cache miss (no entry, or an entry past its TTL), it now calls a new private helper `resolve_remote`, which opens a `TcpStream` to `geo.internal:7070`, writes the IP, reads back the location string, and returns it (trimmed); any connection, write, or read failure — as well as an empty response — is treated as "not found" (`None`). This required adding `std::io::{Read, Write}` and `std::net::TcpStream` imports plus a `GEO_SERVER_ADDR` constant; no external dependencies were added and `cargo build` succeeds. The key consequence for reviewers is that `resolve` is no longer a cheap in-memory table lookup: it now performs blocking network I/O on every cache miss. The candor diff confirms this — a new `Net` effect originates in `resolve_remote` and propagates transitively through all 6 callers up to `main` (`service::GeoService::locate`/`batch`, `api::lookup_one`/`lookup_many`, `report::summary`, and `main`). Most notably, `report::summary` — documented as a periodic dashboard refresh that runs "on a tight interval and assumes it's cheap" — will now make a network round-trip per unresolved IP (including the uncached `192.0.2.5`), so its latency and failure profile change and it may want a timeout or rate limiting.
