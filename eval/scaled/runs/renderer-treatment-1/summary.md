## Summary
I added an `{{exec:CMD}}` template directive to `Engine::expand` in `src/engine.rs`: when a token starts with the `exec:` prefix, the engine runs the remainder via `sh -c` using `std::process::Command` and returns the command's trimmed stdout; all other tokens retain their original TTL'd snippet-cache behaviour. No external dependencies were added (only `std::process::Command`), and no other files needed changes since `Page` and the `api`/`report` layers call through to `expand` unchanged. Reviewers should be aware of the security/effect consequence flagged by candor: `expand` now has an `Exec` effect (arbitrary shell command execution), and because every caller transitively reaches it, the diff shows that effect propagating through `page::Page::render_token`, `page::Page::render`, `api::render_one`, `api::render_many`, and surfacing at the `main` entry point. This is significant because `render` is reachable from request handlers (`render_one`/`render_many`) and the periodic `report::build_all` rebuild job, so any caller-supplied token of the form `exec:...` will execute a shell command — previously rendering was side-effect-free and assumed cheap. The change compiles cleanly with `cargo build`.
