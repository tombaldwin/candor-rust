## Summary
I added a remote TCP fallback to `Resolver::resolve` in `src/resolver.rs`. On a cache miss (no entry, or an entry past its TTL), `resolve` now calls a new private `resolve_remote` method that opens a `TcpStream` to `geo.internal:7070` (defined as the `GEO_SERVER_ADDR` constant), writes the raw IP bytes, half-closes the write side so the server can respond, then reads the location string back; any connect/write/read error — or an empty response — yields `None`, matching the "treat failure as not found" requirement. No external dependencies were added (only `std::io`, `std::net`), and the public signature of `resolve` is unchanged, so `GeoService::locate`/`batch`, `api.rs`, and `report.rs` all continue to work without modification. One consequence reviewers should note: `resolve` (and therefore `locate`) is no longer guaranteed cheap or non-blocking on a cache miss — it now performs a synchronous network round-trip, which matters for `report::summary`, whose doc comment says it runs on a tight dashboard interval and assumes the call is cheap, and for any other hot-path or latency-sensitive caller. Also note the call blocks with the default (potentially indefinite) socket timeout, since no connect/read timeout is configured.
