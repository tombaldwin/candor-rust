## Summary
I added a remote fallback to `Resolver::resolve` in `src/resolver.rs`: when there is no fresh cached entry for an IP (cache miss or TTL-expired), it now calls a new private helper `resolve_remote`, which opens a `TcpStream` to `geo.internal:7070`, writes the IP, reads back the location string, and treats any connect/write/read failure (or empty response) as "not found". No external dependencies were added — only `std::net::TcpStream` and `std::io::{Read, Write}`. The key consequence for reviewers is that `resolve` is no longer a cheap in-memory table lookup: candor's `diff .candor/baseline` confirms a new `Net` effect introduced in `resolve_remote` that propagates transitively through `resolve` to all 6 callers across 4 files (`service::GeoService::locate`, `service::GeoService::batch`, `api::lookup_one`, `api::lookup_many`, `report::summary`, and `main`). Most notably, `report::summary` — the periodic dashboard refresh that runs on a tight interval and assumes resolution is cheap — will now perform a blocking network round-trip on every cache miss, which is a latency/availability risk worth flagging. The change compiles cleanly via `cargo build`.
