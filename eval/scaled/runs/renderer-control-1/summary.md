## Summary
I added an `exec:CMD` template directive to `Engine::expand` in `/tmp/proj-02cde02c0b/src/engine.rs`. When the requested token begins with the `exec:` prefix, the engine runs the remaining string as a shell command via `Command::new("sh").arg("-c").arg(cmd)`, and on success expands the token to the command's stdout trimmed of surrounding whitespace; if the command fails to spawn, exits non-zero, or produces non-UTF-8 output, it returns `None`. All other tokens keep their existing TTL'd snippet-cache behaviour unchanged. The only new code is an `import` of `std::process::Command` and the prefix branch at the top of `expand`, so no external dependencies were added and the rest of the codebase (the `Page` and `api`/`report` layers that call `expand` through `render_token`) is unaffected — an unknown/failed `exec:` token simply renders as the literal `{{exec:...}}` just like any other miss. Reviewers should note that this evaluates arbitrary shell input synchronously on the same thread as rendering, so untrusted templates could execute arbitrary commands and a slow command will block the (assumed-cheap) render/rebuild paths in `report::build_all` and the API handlers.
